# Дурак — realtime карточная игра (тестовое задание)

Многопользовательская игра в "Дурака" на двоих: Flutter-клиент (web + mobile из одной кодовой базы) и Node.js/TypeScript бэкенд с realtime-синхронизацией через Socket.IO.

Сделано как демонстрация подхода к разработке сложных игровых сервисов: чистая доменная логика без зависимостей от фреймворков, тонкие адаптеры к транспорту (REST/WebSocket), и клиент, который ничего не знает о деталях сети.

## Архитектура

```
server/                     Node.js + TypeScript
  src/domain/                — чистые правила игры, без I/O
    card.ts                 — карта, масть, сравнение (бьёт/не бьёт)
    deck.ts                 — колода, тасование
    game-state.ts            — состояние партии
    durak-engine.ts          — конечный автомат: applyAction(state, action) -> state | error
  src/application/
    room-service.ts          — жизненный цикл комнаты (создание/вход/применение хода)
  src/infrastructure/
    http/rooms-router.ts     — REST: создать комнату, проверить существование
    socket/game-gateway.ts   — Socket.IO: join_room, game_action, приватные game_state
    game-view.ts             — проекция состояния под конкретного игрока (чужая рука скрыта)

app/                         Flutter (web + mobile)
  lib/domain/                — сущности и абстракция GameRepository (без knowledge о сокетах)
  lib/data/                  — RoomApi (REST), SocketGameDataSource, GameRepositoryImpl
  lib/presentation/          — Riverpod state (GameController), экраны, виджеты
```

Ключевое архитектурное решение: **правила игры — чистые функции**. `applyAction` в `durak-engine.ts` не знает о сети, сокетах или базе данных — он принимает состояние и действие, возвращает новое состояние или ошибку. Это даёт:
- Полное покрытие unit-тестами без поднятия сервера (`server/src/domain/durak-engine.test.ts`, 11 тестов).
- Простую замену транспорта — сейчас Socket.IO, но игровая логика не изменится, если завтра понадобится другой протокол.

На клиенте то же самое зеркалится через `GameRepository` — presentation-слой обращается только к абстракции, поэтому в widget-тестах используется фейковый репозиторий вместо реального сокета (`app/test/widget_test.dart`).

## Правила и упрощения (MVP)

Реализован классический 2-игровой "Дурак" (36 карт, атака/подкидывание по рангу, отбой козырем/старшей картой той же масти, добор карт после раунда). Сознательно не реализовано (не является ограничением архитектуры — можно добавить в `durak-engine.ts`):
- Перевод карты защищающимся (передача хода).
- Игра 3+ игроков / несколько атакующих одновременно.
- Подкидывание всеми игроками, а не только исходным атакующим.

## Запуск

**Backend**
```bash
cd server
npm install
npm run dev        # http://localhost:3000
npm test           # доменные unit-тесты
```

**Client**
```bash
cd app
flutter pub get
flutter run -d chrome                 # веб
flutter run                           # на подключённом устройстве/эмуляторе
```

Откройте два браузерных окна (или веб + телефон): в первом — «Создать комнату», скопировать код, во втором — «Войти в комнату» с этим кодом.

## Почему так, а не иначе

- **Socket.IO, а не голый WebSocket** — автопереподключение и совместимость с прокси/веб из коробки, что важно для мобильного клиента на нестабильной сети.
- **In-memory RoomService** — осознанное упрощение для тестового задания; интерфейс подготовлен так, чтобы заменить его на Redis-бэкенд, не трогая ни движок игры, ни Socket-шлюз.
- **Riverpod на клиенте** — тестируемый DI без BuildContext, легко подменять зависимости (см. `FakeGameRepository` в тестах).

## Как использовался ИИ (Cursor/Claude) в разработке

Проект собран end-to-end с Claude как основным инструментом: доменная модель и её тесты, инфраструктурные слои (REST/Socket.IO), Flutter-клиент с Riverpod и весь UI написаны и провалидированы (typecheck, unit-тесты, `flutter analyze`, живой прогон в Chrome) в рамках одной сессии. Это отражает то, как предполагается вести разработку в вакансии — максимальная скорость за счёт ИИ при сохранении чистой архитектуры и тестового покрытия.
